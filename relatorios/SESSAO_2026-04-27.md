### 1.5 OpenMetadata — Pipeline Service e integração com Trino (sessão 2026-04-28)

| Problema | Causa raiz | Solução |
| --- | --- | --- |
| "Test Connection" e "Add Ingestion" indisponíveis no OpenMetadata | `openmetadata/server:1.4.0` é Java puro — sem Python nem connectors. Requer container separado `openmetadata/ingestion:1.4.0` | Adicionado serviço `openmetadata-ingestion` no `docker-compose.yml` com Airflow interno |
| Airflow de ingestão não encontrava banco PostgreSQL | O script `ingestion_dependency.sh` usa MySQL por padrão (`DB_SCHEME: mysql+pymysql`); precisava de `AIRFLOW__DATABASE__SQL_ALCHEMY_CONN` apontando para PostgreSQL | Criado banco `airflow_om_db` no PostgreSQL; variável sobrescrita no `docker-compose.yml` |
| `ValueError: Fernet key must be 32 url-safe base64-encoded bytes` | Chave gerada com `tr -d '='` remove o padding obrigatório do base64 | Gerado com `openssl rand -base64 32 \| tr '+/' '-_'` (mantém `=` final) |
| Plugin `openmetadata_managed_apis` não carregava — `AttributeError: partially initialized module` (circular import) | `plugin.py` chama `cached_app()` no nível do módulo; no Airflow 2.7.3 isso causa circular import durante o carregamento de plugins | Criado `infra/openmetadata/plugin.py` sem `cached_app()`, montado via volume sobre o arquivo original |
| Plugin carregava mas endpoints `/api/v1/openmetadata/*` retornavam 404 | Decorador `@security.requires_access(...)` chama `get_airflow_app()` no momento da decoração (import time) — falha porque Flask ainda não inicializou | `plugin.py` patched: monkey-patch de `security.requires_access` por versão no-op antes de chamar `get_blueprint()` |
| Banner "Failed to connect to Airflow — Is the host available at http://localhost:8080?" persistia mesmo com config correto | `openmetadata.yaml` lê host do Airflow de variável de ambiente `PIPELINE_SERVICE_CLIENT_ENDPOINT` (padrão `localhost:8080`), **não** do Pipeline Service salvo na UI | Adicionado `PIPELINE_SERVICE_CLIENT_ENDPOINT: http://openmetadata-ingestion:8080` no container `openmetadata` |
| Deploy do workflow falhava: `HTTPConnectionPool(host='localhost', port=8585): Max retries exceeded` | `openmetadata.yaml` usa `SERVER_HOST_API_URL` (padrão `localhost:8585`) para gerar a URL de callback no workflow — o Airflow tenta `localhost` dentro do próprio container | Adicionado `SERVER_HOST_API_URL: http://openmetadata:8585/api` no container `openmetadata` |
| Formulário do Pipeline Service mostrava `scheme: MysqlConnection` com campos obrigatórios MySQL | OpenMetadata 1.4.0 pré-seleciona MysqlConnection no campo "Metadata Database Connection" | Selecionar **PostgresConnection** no dropdown e preencher com `postgres:5432` / `airflow_om_db` / `dlh_admin` |

> **Dica crítica:** no OpenMetadata 1.4.0, a mensagem de erro "Is the host available at http://localhost:8080?" é um **texto fixo** no template de erro — não reflete o host configurado. O que importa é o valor da variável de ambiente `PIPELINE_SERVICE_CLIENT_ENDPOINT` no container `dlh_openmetadata`.

## 8. Guia de implantação para a equipe GitLab/Kubernetes

> Esta seção destina-se à equipe de infraestrutura responsável por migrar o projeto do ambiente local (Docker Compose) para o cluster corporativo (GitLab CI/CD + Kubernetes).

### 8.1 Repositório e CI/CD (GitLab)

- **Importe o repositório** diretamente do diretório atual — já está em git (`git remote add origin <url-do-gitlab>`).
- Crie um arquivo `.gitlab-ci.yml` na raiz com ao menos três stages: `build` (build das imagens Spark e Airflow), `test` (smoke test nos containers) e `deploy` (apply dos manifests Kubernetes).
- As imagens customizadas são apenas **duas**: `infra/spark/Dockerfile` e `infra/airflow/Dockerfile`. As demais (`postgres`, `minio`, `trino`, `openmetadata`) usam imagens públicas — não precisam de build.
- Publique as imagens buildadas no **GitLab Container Registry** (`registry.gitlab.com/<grupo>/<projeto>/spark:latest` e `.../airflow:latest`) e atualize os manifests Kubernetes para referenciar esse registry.
- O arquivo `.env` **nunca deve ser commitado**. Use **GitLab CI/CD Variables** (Settings → CI/CD → Variables) para armazenar todos os valores sensíveis e injete-os como `envFrom: secretRef` nos Pods.

### 8.2 Secrets e ConfigMaps (Kubernetes)

Crie um `Secret` com as variáveis sensíveis e um `ConfigMap` com as não-sensíveis:

```yaml
# secret-dlh.yaml — nunca versionar com valores reais; gere via CI
apiVersion: v1
kind: Secret
metadata:
  name: dlh-secrets
  namespace: dlh
stringData:
  POSTGRES_USER: dlh_admin
  POSTGRES_PASSWORD: dlh_pass_2026
  MINIO_ROOT_USER: minio_admin
  MINIO_ROOT_PASSWORD: minio_pass_2026
  AIRFLOW__CORE__FERNET_KEY: 46BKJoQYlPPOexq0OhDZnIlNepKFf87WFwLt0nIe3aY=
  AIRFLOW__WEBSERVER__SECRET_KEY: dlh_airflow_secret_2026
  OM_AIRFLOW_FERNET_KEY: 6gUQyTNfuph5LGzMWJdmh0jldDCwm8TFcLoYZg8H7zk=
```

> **Dica de produção:** gere novas chaves Fernet para o ambiente de produção com `python -c "from cryptography.fernet import Fernet; print(Fernet.generate_key().decode())"`. As chaves do `.env` local são apenas para desenvolvimento.

### 8.3 Ordem de dependência dos serviços

Respeite a seguinte ordem de startup ao criar os manifests ou Helm charts — cada grupo só sobe após o anterior estar `Ready`:

1. **postgres** + **minio** (stateful — use `StatefulSet` com `PersistentVolumeClaim`)
2. **minio-init** (`Job` de inicialização — cria os buckets `landing` e `lakehouse`)
3. **hive-metastore** (depende de postgres saudável e minio-init concluído)
4. **spark-master** + **spark-worker** (depende de hive-metastore)
5. **trino** + **airflow-init** (depende de hive-metastore)
6. **airflow-webserver** + **airflow-scheduler** (depende de airflow-init)
7. **elasticsearch** + **openmetadata** (depende de postgres e elasticsearch)
8. **openmetadata-ingestion** (depende de openmetadata)

Use `initContainers` com `wget -q --spider <healthcheck-url>` para garantir a ordem no Kubernetes.

| Volume Docker | Conteúdo | Tamanho sugerido |
| --- | --- | --- |
| `postgres_data` | Metastore, Airflow DB, OpenMetadata DB | 20 Gi |
| `minio_data` | Dados brutos (landing) e Iceberg (lakehouse) | 100 Gi+ |
| `elasticsearch_data` | Índices de busca do OpenMetadata | 10 Gi |
| `airflow_logs` | Logs das DAGs | 10 Gi |

> Em produção, o MinIO pode ser substituído pelo S3/GCS corporativo — basta alterar `MINIO_ENDPOINT` e as credenciais nos Secrets. O código Spark e Trino já usam o protocolo `s3a://` e não precisam de alteração.

### 8.5 Exposição de serviços (Ingress)

Serviços que precisam de `Ingress` ou `LoadBalancer` para acesso dos usuários:

| Serviço | Porta interna | URL sugerida |
| --- | --- | --- |
| Airflow Webserver | 8080 | `airflow.dlh.interno` |
| MinIO Console | 9001 | `minio.dlh.interno` |
| Trino | 8090 | `trino.dlh.interno` |
| OpenMetadata | 8585 | `openmetadata.dlh.interno` |
| Spark Master UI | 8080 | `spark.dlh.interno` |

Os demais serviços (postgres:5432, minio:9000, hive-metastore:9083, spark:7077) são **internos** à rede do cluster — exponha apenas como `ClusterIP`.

### 8.6 Arquivos de configuração com credenciais hardcoded

Dois arquivos Trino contêm credenciais fixas (Trino não suporta variáveis de ambiente nos `.properties`):

| Arquivo | O que contem |
| --- | --- |
| `infra/trino/catalog/iceberg.properties` | `hive.s3.aws-access-key` e `hive.s3.aws-secret-key` do MinIO |
| `infra/trino/catalog/postgresql.properties` | `connection-url`, `connection-user`, `connection-password` do PostgreSQL |

**Solução recomendada para Kubernetes:** monte esses arquivos como `Secret` (tipo `Opaque`) via `volumeMounts` no Pod do Trino, em vez de versionar os valores reais. O `docker-compose.yml` já os monta como `read-only` — a mesma lógica se aplica.

### 8.7 Checklist de validação pós-deploy

Após o deploy no cluster, valide nesta ordem:

- [ ] `kubectl get pods -n dlh` — todos os pods em `Running` ou `Completed`
- [ ] MinIO Console acessível → buckets `landing` e `lakehouse` existem
- [ ] Airflow UI → DAG `dag_ingestao_bronze` visível (pausada por padrão)
- [ ] Executar `dag_ingestao_bronze` manualmente → status `success`
- [ ] Trino CLI: `SELECT count(*) FROM iceberg.bronze.dados;` retorna linhas
- [ ] OpenMetadata → Explore → Tables → serviço `trino_dlh` mostra tabelas Iceberg
- [ ] OpenMetadata → Settings → Pipeline Services → `airflow_openmetadata` → Test Connection → sucesso
