O modelo canônico em dois diagramas

Cinco sistemas de origem, seis modalidades de arquivo, uma única tabela de destino. Esta página mostra o percurso que todo dado faz — e como, a partir de qualquer número na camada final, se volta ao arquivo bruto que o gerou.

versão 3 · atualizado em 2026-09-08 · fonte: canonico/modelo_canonico.yaml

Por quê As duas teses que os diagramas servem

Toda decisão de modelagem aqui existe para sustentar uma destas duas afirmações. Se um detalhe do desenho não ajuda nenhuma delas, ele não deveria estar no desenho.

Heterogeneidade
A arquitetura ingere e integra dados de tipos muito diferentes — JSON, planilha, texto livre, imagem, áudio, PDF — sob um modelo canônico único. A coluna MODALIDADE_ORIGEM_COD em EVENTO é o que permite contar quantas formas físicas de dado uma consulta atravessou.
Linhagem
Dá para rastrear qualquer número da camada final até o arquivo que o originou, incluindo qual modelo de IA fez a extração e com que versão de prompt. Os campos ARQUIVO_IDT e EXTRACAO_IDT em EVENTO são os dois elos dessa corrente.

Diagrama 1 O processo: da fonte à camada Silver

O dado desce por camadas (o padrão Medallion): primeiro é guardado cru, depois catalogado sem ser interpretado, e só então convertido para o formato canônico. Cada camada tem um trabalho e só um.

  • Retângulo — uma tabela ou etapa
  • Hexágono — um processo (a transformação)
  • Cilindro — um armazenamento de arquivos
  • Seta cheia — o dado flui nesse sentido
  • Seta pontilhada — um ponteiro: a linha aponta para outra
  • Seta grossa — o fluxo principal

  1. Fontes

    Cada sistema entrega o que já produz, no formato em que produz. O C2_A manda JSON com a geometria embutida; o RELPER, uma planilha — ou o mesmo formulário impresso, assinado e escaneado; a rede de rádio, um arquivo de áudio. Nada é adaptado na origem.

  2. landing/

    O arquivo cai no armazenamento de objetos exatamente como chegou, byte a byte. Nenhum campo é lido ainda. Guardar antes de interpretar é o princípio de schema-on-read: pode-se ingerir uma fonte antes de modelá-la.

  3. Bronze — ARQUIVO e EXTRACAO

    Duas tabelas registram o payload sem interpretá-lo. ARQUIVO cataloga cada binário — onde está, seu hash, seu tipo. EXTRACAO grava uma linha por inferência de IA: qual ferramenta (reconhecimento óptico, transcrição de fala, um modelo de linguagem local), qual modelo, qual versão de prompt, quanto tempo levou.

  4. De / para — modelo_canonico.yaml

    O job de transformação lê o YAML e, para cada campo de cada fonte, aplica a regra ali declarada. Não há if fonte == ... no código: integrar uma fonte nova é acrescentar um bloco no arquivo. É aqui que as tabelas de consulta entram — REF_UNIDADE traduz 1a Cia Fuz no código da unidade, REF_GAZETTEER troca BR-154 km 43 por uma coordenada, REF_ABREVIATURA resolve Fz para Fuzil.

  5. Silver — EVENTO e SITUACAO_UNIDADE

    Todas as fontes desembocam em EVENTO, uma tabela só, com o que toda fonte tem em comum: quem reportou, quando, onde, que tipo de fato, por qual sistema chegou, de que arquivo veio. O que só o RELPER tem — efetivo, baixas, viaturas, dias de suprimento — vai para a extensão SITUACAO_UNIDADE, a única que existe.

Diagrama 2 A estrutura: quais tabelas apontam para quais

O mesmo modelo visto pelas chaves. As caixas listam só as colunas que importam para a leitura — PK marca a chave primária (identifica a linha), FK marca a chave estrangeira (aponta para a linha de outra tabela).

REF_GAZETTEER e REF_ABREVIATURA não aparecem como ligação porque não são chave estrangeira de nada: elas são consultadas durante a transformação, e o resultado já entra gravado em EVENTO e SITUACAO_UNIDADE. REF_UNIDADE aparece porque EVENTO.UNIDADE_REPORTANTE_COD guarda o código que ela define — e aponta para si mesma, porque toda unidade tem uma superior (menos a brigada, no topo).

Referência As cinco fontes

Cada linha é um bloco em fontes: no YAML. Uma fonte pode ter mais de uma modalidade — o RELPER chega como planilha ou como PDF assinado, e o C2_B, como texto ou como foto.

Fonte Modalidade Bloco no YAML Grava em Passa por IA?
C2_A JSON posicao, mcc EVENTO Não — geometria já vem nativa
C2_B TEXTO relato EVENTO LLM: tipo, função de combate, prioridade, confiabilidade, credibilidade
C2_B IMAGEM incidente EVENTO + ARQUIVO Não — a coordenada vem do metadado da foto
RELPER PLANILHA situacao EVENTO + SITUACAO_UNIDADE Não — leitura de célula
RELPER PDF situacao_digitalizada EVENTO + SITUACAO_UNIDADE OCR + LLM: unidade reportante
FOGOS PDF relatorio_bombardeio EVENTO OCR + LLM: data, prioridade
VOZ AUDIO transcricao EVENTO Transcrição de fala + LLM: data, prioridade, função
Toda linha marcada com IA gera pelo menos uma linha em EXTRACAO — é o que torna a extração auditável.

Referência Vocabulário das transformações

O nome que aparece em transformacao: no de/para. O código de cada uma vive no job de transformação, não no YAML — o YAML só diz qual aplicar a cada campo.

direto
Copia o valor sem mexer.
json
Extrai do payload JSON pelo caminho indicado.
celula
Lê uma célula da planilha pelo cabeçalho decretado no formulário.
ts_iso / ts_br
Texto vira data — no formato ISO ou no formato brasileiro.
ponto_de_latlon
Par de números vira ponto geográfico.
geojson_para_wkt
Geometria em GeoJSON vira o mesmo em WKT (o texto padrão do modelo).
dms_para_ponto
Coordenada em grau-minuto-segundo, escrita por extenso, vira ponto.
decametrica_para_ponto
Coordenada métrica militar (ex.: 03250-10550) vira ponto.
gazetteer
Nome de lugar vira ponto, consultando REF_GAZETTEER. Não converte — consulta.
abreviatura
Abreviatura digitada vira termo, consultando REF_ABREVIATURA.
dominio
Valor da origem vira valor canônico, pelos sinônimos da lista fechada.
referencia
Valor da origem vira o código de uma tabela de consulta.
constante
Grava um valor fixo, igual para toda linha daquela fonte.
derivado
Calculado por uma regra declarada no próprio campo de destino.
split_escala
Um campo de origem, dois de destino: B2 vira confiabilidade B e credibilidade 2.
sobra
Tudo que o formulário não previa vai para uma coluna JSON, com o nome que a unidade deu.
